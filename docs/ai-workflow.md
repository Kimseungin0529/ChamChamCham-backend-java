# AI 개발 절차

이 문서는 작업 단계의 최소 절차를 정한다. 공통 규칙은 [AGENTS.md](../AGENTS.md)에만 둔다. 단계별 Markdown 파일을 추가하기 전에 실제로 반복되는 필요가 있는지 확인한다.

## 1. 설계

- 요청의 완료 조건과 변경하지 않을 API·데이터 계약을 적는다.
- 변경할 모듈과 외부 시스템을 확인한다. 운영 서비스나 원본 저장소가 대상이면 작업을 멈추고 개인 환경으로 바꾼다.
- 선택지가 있으면 가장 단순한 구현과 그 제약을 설명한다.

## 2. 개발

- 동작 변경에는 재현·회귀 테스트를 먼저 작성한다.
- 한 기능 묶음씩 수정하고 해당 모듈 테스트를 실행한다.
- 새 추상화·의존성을 넣기 전에 현재 구조로 해결할 수 있는지 확인한다.

## 3. 검토

- 변경 파일마다 요청과의 관련성을 확인한다.
- 계층 의존 방향, `member` 명칭, `@Valid`의 API 경계, 비밀값·개인 정보 노출 여부를 확인한다.
- API 경로·JSON·DB·환경 변수·배포 영향과 테스트 결과를 기록한다.
- 개인 저장소 PR의 `Backend tests` 결과를 확인한다. 이 워크플로는 테스트만 실행하며 배포 작업이나 운영 비밀값을 사용하지 않는다.

## 4. 실제 API 시험

- 로컬 서버 또는 사용자가 소유한 별도 테스트 환경에서만 실행한다.
- 테스트 계정·데이터를 사용하고, 호출 대상 URL과 Spring 프로필을 실행 직전에 확인한다.
- HTTP 상태와 응답 본문뿐 아니라 DB·Redis의 기대 변화와 오류 응답도 확인한다.
- 원본의 운영 API, DB, 서버, Docker Hub 저장소, 앱 배포 계정은 시험 대상으로 쓰지 않는다.

## 5. 인계

- 정확히 실행한 명령과 결과, 미실행 검사, 남은 위험을 남긴다.
- 다음 작업자는 통과한 기준선과 변경된 계약을 먼저 읽고 이어서 진행한다.
