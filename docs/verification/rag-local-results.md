# 공식 문서 적재와 실제 검색 검증 결과

2026-11-14 개인 로컬 환경에서 수행했다. **문서 적재 → 실제 임베딩 → PostgreSQL 검색 → 답변 모델 직전 프롬프트**를 검증했다. 실제 답변 모델은 호출하지 않았으므로 코칭 품질 검증 완료를 뜻하지 않는다.

## 무엇을 실행했나

농촌진흥청 공식 웹 문서 2개에서 재배 관련 문단을 선택했다. 선택 본문은 490자·748자이며 각각 하나의 조각으로 저장했다. 작물은 두 문서 모두 명시한 천궁이다. 원래 팀원이 사용한 PDF 5개·580개 기술문서 조각을 복원한 것은 아니다.

실제 `bge-m3` F16(566.70M)로 본문과 검색어를 임베딩했다. DB를 다시 조회해 본문·출처 metadata가 원본 조각과 같은지, 벡터가 1024차원인지 확인했다. 같은 문서를 두 번 적재해도 원문 조각은 2개였다. 검증용으로 같은 본문의 다른 작물·FARMING_RECORD 조각을 2개 더 넣고 검색 결과에서 제외되는지 확인했다.

실제 `RecordFeedbackGenerationService`가 만드는 요청을 Spring AI 1.1.8 `PgVectorStore`로 실행했다. 코사인 거리와 HNSW 인덱스 생성 설정을 사용했다. 작은 테이블에서 PostgreSQL이 실제 선택한 실행 계획의 성능은 조사하지 않았다.

8개 합성 상황마다 다음 6조건을 실행해 **총 48개 비교 기록**을 남겼다.

- 기본 검색만 / 기본 검색에 메모 검색 추가
- 유사도 기준 0 / 0.5 / 0.55
- 각 검색의 topK=3, 작물·작업·날짜·기록 당시 날씨 고정, 실시간 날씨 없음

최종 근거가 있으면 실제 프롬프트를 캡처한 뒤 테스트 대역에서 답변 모델 호출을 중단했다. 프롬프트에 문서 ID·본문·전체 메모가 포함되고 같은 문서 ID가 중복되지 않는지 확인했다. 별도의 임계값 1 조건에서는 근거가 없어 `INSUFFICIENT_EVIDENCE`가 발생하고 모델 호출 단계에 도달하지 않았다.

## 실제 비교 결과

아래 숫자는 최종 프롬프트에 들어간 **고유 문서 조각 수**다. `0`이면 검색 근거가 없어 프롬프트 생성 전에 중단됐다. 이번 자료에서는 0과 0.5의 최종 조각 수가 모두 같았다.

| 상황 | 문서가 직접 다루는 내용 | 0.5 기본만 | 0.5 메모 추가 | 0.55 기본만 | 0.55 메모 추가 |
|---|---|---:|---:|---:|---:|
| 고온 피해 우려 | 고온 취약성·일반 관리 | 2 | 2 | 0 | 2 |
| 적합지에서도 물 관리 필요 | 이상기상 시 물 관리 | 2 | 2 | 0 | 2 |
| 흙·잎 마름 | 고온기 토양 수분 관리 | 2 | 2 | 0 | 2 |
| 질소 과다 사용 우려 | 과다 질소 위험·일반 영양 관리 | 2 | 2 | 0 | 2 |
| 병든 식물의 확산 우려 | 병든 식물 제거·증상 확인 | 2 | 2 | 0 | 2 |
| 핵심 질문이 메모 120자 뒤 | 질소·영양 관리이지만 검색어에서 핵심 누락 | 2 | 2 | 0 | 0 |
| 특정 농약 제품·희석 배수 | **자료에 없음** | 2 | 2 | 0 | 0 |
| 현재 천궁 도매가격 | **자료에 없음** | 2 | 2 | 0 | 0 |

전체 48조건 중 37조건에서 프롬프트를 캡처했고, 11조건은 검색 근거가 없어 중단됐다. 이것은 자동 검사 통과 횟수이며, 37개가 모두 질문에 충분한 근거를 가졌다는 뜻이 아니다. 지원하는 문단의 존재 여부는 실행 전에 정한 sourceId와 본문 구절을 기준으로 대조했다. 농업 전문가의 임상·현장 효과 평가는 수행하지 않았다.

## 결과를 어떻게 이해해야 하나

### 1. 유사도 기준은 실제 검색 요청에 전달된다

기본 검색어는 `천궁 관수 재배 관리 약용작물`이다. 두 문서의 점수는 각각 약 **0.5295, 0.5210**이었다. 0.5에서는 둘 다 검색되지만, 0.55에서는 둘 다 제외됐다. 테스트는 설정값과 실제 요청값, 반환 점수를 대조했다. 임계값 누락을 재현하거나 제품을 새로 수정한 작업이 아니라 **현재 구현이 실제 DB 검색에도 적용되는지** 확인한 작업이다.

유사도는 이 모델·문서·검색어 조합의 벡터 점수다. 문서 내용이 질문에 정답을 제공하는 확률로 해석하면 안 된다. 각 검색이 따로 기준을 적용하며, 여러 검색 중 하나에서 통과한 문서도 최종 근거에 포함될 수 있다.

### 2. 메모가 검색 점수를 바꿨지만 개선 효과는 조건에 따라 다르다

질소 과다 메모 검색에서는 2025년 문서가 약 **0.6689**, 2017년 문서가 약 **0.5603**이었다. 기본 검색만으로는 둘 다 0.55를 넘지 못했지만, 메모 검색에서는 통과했다. 직접 근거가 있는 첫 5개 상황에서 같은 차이가 관찰됐다.

반면 0.5에서는 메모를 추가하기 전부터 두 문서가 모두 반환돼 최종 근거 집합이 같았다. 원문이 2개이고 검색당 최대 3개를 받는 작은 자료이므로, 메모 검색이 전반적인 검색 품질을 개선했다고 일반화할 수 없다. 메모 추가가 더 높은 점수의 문서를 항상 최종 맨 앞으로 옮기는 것도 아니다. 제품은 검색 결과를 문서 ID 기준으로 합치며 전체 재정렬·최종 topK 제한은 하지 않는다.

0.55가 최적의 기준이라는 결론도 아니다. 값을 올리면 자료 밖 상황을 줄이는 동시에 필요한 근거를 놓칠 수 있다. 문서 수·작물·상황·정답 근거를 늘린 뒤 따로 평가해야 한다.

### 3. 120자 뒤 핵심은 검색어에 반영되지 않았다

긴 메모의 뒤쪽에 질소·칼슘·칼륨 질문을 배치했다. 실제 메모 검색어에는 앞부분의 관수 작업 정리만 들어갔다. 해당 검색은 0.5에서도 반환 결과가 없었다. 전체 메모는 프롬프트 입력에 보존되지만, 검색어는 현재 앞 120 UTF-16 코드 단위까지만 사용한다.

0.5에서는 기본 검색이 두 문서를 확보해 프롬프트가 만들어졌고, 0.55에서는 기본·메모 검색이 모두 비어 중단됐다. 이 사례는 전체 메모 보존과 검색어 반영을 각각 확인해야 하는 이유를 보여 준다.

### 4. 검색 결과 없음과 질문에 답할 자료 없음은 다르다

특정 농약의 희석 배수와 현재 도매가격은 선정 문서에 없다. 그런데 0.5에서는 기본 검색이 일반 재배 문서 2개를 반환해 프롬프트가 만들어졌다. 농약 메모 검색 자체도 약 **0.5370, 0.5291**의 점수로 두 문서를 반환했다. 가격 메모 검색은 2017년 문서를 약 **0.5269**로 반환했다.

현재 검색 단계가 자동으로 차단하는 조건은 **검색 조건을 통과한 문서가 0개인 경우**다. 반환 문서가 질문을 충분히 뒷받침하는지의 의미 판단은 이 조건에 포함되지 않는다. 따라서 경험 설명은 “참고 문서가 없으면 코칭을 생성하지 않음”보다 **“검색 조건을 통과한 기술문서가 없으면 생성 요청을 중단함”**이라고 범위를 명확히 하는 것이 정확하다.

이번에는 답변 모델을 호출하지 않았으므로 이런 입력으로 모델이 실제로 무엇을 답할지는 확인하지 않았다. 제품 동작이나 임계값을 임의로 바꾸지 않았다.

원문 URL·원문 해시·선택 본문 해시는 [출처 기록](rag-local-sources.json)에 있다. 원문 HTML과 선택 문단은 `/private/tmp/chamchamcham-rag-retrieval/`에 보존했다. DB 재조회는 `api/build/rag-local-verification/database.json`, 실제 검색어·점수·문서·전체 프롬프트는 같은 폴더의 `comparisons.json`에 있다. [48조건 비교표](rag-local-results.csv)는 원문 전체를 포함하지 않는 요약본이다.

프롬프트에는 문서 ID·제목·본문이 들어간다. 원문 URL은 DB metadata와 로컬 추적 자료에 보존했다. 실제 답변 이후 citation 응답에 URL이 어떻게 노출되는지는 검증하지 않았다. 웹 문서이므로 PDF 페이지 번호는 만들지 않았다.

## 검증·리뷰·남은 범위

실행 명령은 [재실행 안내](rag-local.md)에 있다. 검증용 통합 테스트 1개 안에서 48조건과 별도 빈 결과 조건을 검사했고 통과했다. Python 문단 분할·과대 문단 거부·멎은 프로세스 종료 검사 3개도 통과했다. 최종 루트 `./gradlew test --offline --console=plain` 결과는 아래 실행 기록에 남긴다.

독립 리뷰에서 양성 결과 필수 확인, 원문·DB·검색 본문 대조, 새 환경의 PG 이미지 준비 안내, 검증 시간 제한을 보강했다. 실제 정상 임베딩·검색·프롬프트 도달로 보강 결과를 확인했다. 기존 데이터와 제품 코드는 변경하지 않았다. 이 실행의 일회용 DB·모델 컨테이너는 종료 시 제거했고 모델 캐시는 유지했다.

최초 모델 다운로드에서 HTTP 500이 한 번 발생했다. 재시도로 다운로드가 완료됐으며, 네트워크 지연의 세부 원인은 확정하지 않았다. 중단 직전 완료 상태를 재확인하지 못하고 컨테이너를 멈춰 첫 임베딩 실행도 끊겼다. 이후 완성된 모델 파일 4개의 SHA-256을 확인한 뒤 정상 재실행했다. 별도의 모델 파일 수동 복구나 모델 교체는 하지 않았다.

남은 작은 개선은 준비 단계 실패 시 이전 `gradle.log`가 남을 수 있다는 점이다. 비교·DB·인프라 결과는 실행 시작 시 삭제하므로 이를 성공 결과로 재사용하지 않는다. 실패 진단 시 해당 실행의 콘솔과 인프라 exitCode를 함께 확인해야 한다.

이번에는 원래 팀 환경의 성능, 전체 작물·작업 유형의 답변 품질, 실제 chat 모델, 인증을 포함한 HTTP 요청부터의 전체 연결, 농약 적합성, 현재 날씨·가격을 검증하지 않았다. 후속 작업은 문서 범위를 확장한 정답 자료와 자료 밖 사례, 실제 답변·인용·API 통합을 별도 계획으로 검증하는 것이다.

최종 실행 결과: 전체 1410건, 실패 0건, 오류 0건, 조건부 건너뜀 15건(통과 1395건). 로컬 통합 테스트는 별도 실행에서 통과했고 기본 전체 실행에서는 조건부로 건너뛴다. 전용 실행은 7분 19초였으며 검색 성능 벤치마크 수치로 해석하지 않는다. JVM CDS 경고는 있으나 실패는 없다.
