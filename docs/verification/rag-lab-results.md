검증일: 2026-11-15 KST. 작업 브랜치: `chore/rag-local-persistent`.

## 이번에 완료한 것

공식 문서 원문·검색 조각·PostgreSQL 벡터 DB·기존 `bge-m3` 캐시를 보존하는 환경과 직접 검색하는 실행 도구를 추가했다. 제품 API·업무 로직·프롬프트는 변경하지 않았다. 답변 모델과 OpenClaw를 실행하거나 외부 AI를 호출하지 않았다. 새 이미지·모델 다운로드도 하지 않았다.

Docker 이미지 식별값과 모델 digest는 앞 단계와 동일하다. 구체적인 값은 로컬 `.local/rag/results/environment.json`과 앞 단계의 `rag-local-environment.json`에 있다. PostgreSQL은 `pgvector/pgvector:0.8.5-pg16`의 확보된 digest, Ollama는 확보된 digest로 고정했다. 임베딩은 `bge-m3:latest`, digest `7907646426070047a77226ac3e684fbbe8410524f7b4a74d02837e43f2146bab`을 확인했다.

최초 실행은 검토된 원문을 기존 임시 폴더에서 `.local/rag/corpus/`로 옮겼다. 이후 검증은 보존한 자료를 사용했다. 이 폴더와 비밀번호·결과·백업은 Git 제외 여부도 확인했다.

## 직접 입력한 검색의 예

실제 검색어 `천궁 고온 수분 관리`, 임계값 `0.5`, topK `3`:

| 반환 문서 | 유사도 |
|---|---:|
| 고온 취약한 약용작물, 재배 관리 필수 (2025) | 0.653694 |
| 천궁·당귀 재배 전에 안전 재배지인지 확인하세요 (2017) | 0.622160 |

검색 결과 본문·ID·metadata가 보존한 공식 조각과 같은지 검사했다. 이 숫자는 해당 검색어와 문서 사이의 유사도이며, 답변 정답률이나 65% 정확도를 의미하지 않는다. 문서가 반환된 사실만으로 질문에 답할 충분한 근거가 있다고 판단하지 않는다.

## 발견한 문제와 해결

- Spring AI가 생성한 metadata 열 타입을 처음에 `jsonb`로 예상했지만 실제는 `json`이었다. 실제 스키마와 실패 보고서를 대조해 검사 기대값만 고쳤다. 테이블을 변경하지 않았다.
- 종료된 소켓의 TIME_WAIT를 실행 중인 서비스로 오인했다. 실제 소켓 회귀 검사로 재현한 뒤 종료 흔적을 허용하도록 고쳤다. 실제 리스너를 점유한 포트는 계속 거부한다.
- 독립 리뷰는 Critical 0/Important 2/Minor 2건을 보고했다. 사용자 스키마 누락과 사전 검사 실패 후 이전 결과 잔존을 회귀 검사로 재현해 수정했다. 사용자 스키마·관계·확장 검사를 DDL 전에 수행하고 결과를 사전 검사 전에 무효화한다.
- 리뷰의 초기 복사 중단 문제는 처음 실행의 재시도를 막으므로 중요하게 취급했다. 검토된 임시 복사를 완료한 뒤 정식 폴더로 바꾼다. 복사 실패·재시도 회귀 검사가 통과했다. 비용은 최초 준비 시 임시 복사 공간이다.
- 리뷰의 식별 토큰 보고서 노출은 로컬 신뢰 확인값 보호 문제로 중요하게 취급했다. 실제 거부 검사로 노출을 확인한 뒤 값 대신 일치 여부를 검사하도록 고쳤다. 같은 거부를 유지하면서 토큰 미노출을 확인했다. 실패 시 실제 값은 설정에서 직접 대조해야 한다.

독립 리뷰어는 파일을 읽기 전용으로 확인했다. 수정 후 재리뷰를 반복하지 않고 작성자가 실패 재현·수정 후 검사와 전체 테스트로 확인했다. 보류한 리뷰 항목은 없다.

## 남은 범위와 해석

이번 작업은 직접 재실행할 수 있는 **검색 실습 환경**의 완료다. 문서 2개는 천궁의 고온·수분 관련 일부 근거이며 534개 작물·8개 작업 전체를 대표하지 않는다. 답변 모델 호출·OpenClaw 에이전트 설정 복원·전체 API 실행·코칭 정답률은 미실행이며 이번 승인 범위에서 제외했다.

백업 복구는 같은 전용 PostgreSQL 인스턴스의 새 DB로 확인했다. 다른 컴퓨터나 인스턴스 장애 복구, 대규모 인덱스 성능 검사는 수행하지 않았다. `ddl-auto=create`를 사용하는 전체 앱은 이 DB에 연결하지 않았다.

다음 단계는 별도 계획으로 답변 모델과 OpenClaw를 연결하고 기존 기록·피드백 API를 실행하는 것이다. 이어 공식 자료와 사전 정답 사례를 확대해 기준 성능을 측정하고, 조정용 사례와 분리한 평가 사례로 정확도 개선 여부를 비교한다.
