# 농업 행위와 데이터 관계를 어디까지 확인했는가

## 확인의 단위

코드의 8개 작업 유형과 상세 25필드의 전체 목록은 [필드표](rag-api-fields.csv)에 있다. 기존 [51사례 범위표](record-local-coverage.csv), [90개 PostgreSQL 검사 결과](record-local-results.md)를 재사용한다. 이번에는 실제 TCP API·로그인·비동기·검색·모델을 연결한 부분을 추가 검증한다. 이전 90개를 이번 단계에서 모두 재실행했다고 합산하지 않는다.

공통 입력은 농지·작물·작업 일시·날씨 문자열·정수 기온·30~500자 메모·사진 ID 목록·입력 모드다. 사진은 개수만 AI에 전달하며 영상/사진 진단을 한 것이 아니다. `VOICE` enum이 있다는 사실과 음성 제공자 실행 검증도 구분한다. 이번 요청은 `MANUAL`이다.

### 총살포량

사용자가 피그마를 확인해 합의한 의미는 농약과 물을 합친 최종 살포액 전체량이다. 농약 그램/밀리리터와 총살포액 밀리리터는 따로 저장한다. 질량과 부피를 더하거나 임의의 밀도로 바꾸지 않는다. 기존 AI 문구 ‘약을 섞은 물의 양’은 합의된 의미와 차이가 있지만 사용자 지시에 따라 유지했다. 이 검증은 제품의 사용량 적합성 판정을 대신하지 않는다.

### 품목명·상표명과 조회 응답

실제 실행에서 `pesticideName`이라는 같은 JSON 이름도 조회 응답은 `Pesticide.itemName`(품목명), AI 문맥은 `Pesticide.brandName`(상표명)을 사용함을 확인했다. 양·단위·제품 UUID가 바뀐 것은 아니지만 표시 의미가 다르다. 두 문자열이 같다고 가정한 초기 비교는 잘못된 가정이었다. 실제 DB의 두 속성을 별도로 대조하고 차이는 관찰 결과로 남겼다. 명칭/응답 계약은 변경하지 않는다.

### 이력과 등록조건

기록은 DB에 남지만 현재 RecordFeedbackContextAssembler는 대상 기록 하나를 조립한다. 이전 살포·비료·관수 이력을 AI에 자동으로 제공하는 경로가 아니다. 따라서 이번 답변을 보고 누적 농약 횟수, 수확 전 안전기간, 연작 이력이 자동 검증됐다고 표현하면 안 된다.

농약 도메인에는 `PesticideApplication`의 작물명 문자열×농약×병해충 관계와 사용 조건 문자열들이 있다. 기록 저장 서비스가 이 관계를 조회해 적합성을 판정하는 것은 아니다. 현행 공개 PSIS 등록 검색의 열 구조는 확인했지만 실제 제품별 현행 등록 데이터의 완전한 로컬 복제본은 확보하지 않았다. 회원가입·키 신청·비공개 접근은 하지 않았다. 이번 실습의 제품/병해충은 명시적인 합성 자료다.

[PSIS 등록 검색](https://psis.rda.go.kr/psis/agc/res/agchmRegistStusLst.ps), [PSIS 농약 선택 원칙](https://psis.rda.go.kr/psis/cont/contentMain.ps?menuId=PS00316).

카탈로그는 이름·externalNo·분류만 보유하며 학명·동의어·품종·생육 기간이 구조화돼 있지 않다. 534개 seed 행과 9개 분류 구조를 확인한 결과를 재사용하지만 이번 실습 DB에 준비한 작물은 3개다. ‘534종의 코칭 정확도를 검증했다’는 결론이 아니다.

구기자 자료의 ‘구기자/구기자나무’ 대응은 같은 매뉴얼의 제목/본문을 대조해 실습 적재에서 수동 처리했다. 제품에 동의어 검색 기능을 추가한 것이 아니다. 천궁의 종/재배종 명칭은 자료·연도별 표현 차이가 있어 품종을 자동 통합하지 않았다. 카탈로그명만으로 하위 재배종을 확정할 수 없다는 한계가 남는다.

## 출처에서 실제로 제외한 것

원문 9개와 검색 문단 26개는 모두 별도 캐시에 보존하며 [출처 목록](rag-api-sources.json)에 URL·해시·조회 시각·선택 범위·제외 이유가 있다.

- 인체 효능·민간요법·가공 레시피·광고·가격/유통 조언은 재배 근거에서 제외했다.
- 구기자 매뉴얼 PDF17쪽의 본문은 2년차 이후 가리·인산에 대한 설명을 하지만 표의 가리 배분과 맞지 않는 부분이 있다. 해당 정량 처방을 임의로 하나 선택하지 않았다.
- 과거 자료의 농약명·배수·수확 전 기간을 현재 등록 사용법으로 넣지 않았다.
- 참당귀의 이식 후 80~100일은 잎 수확 문단의 조건이다. 뿌리 수확 시기와 통합하지 않았다.
- 청감의 호광 수분수·수형·적심 조건은 해당 품종 조건을 붙였다. 다른 모든 구기자의 필수 조건으로 일반화하지 않았다.

임계값 0.5는 검색 설정이며 ‘문장이 농업적으로 옳다’는 확률이 아니다. 다른 작물 문서의 혼입, 필요한 문단 회수, 단위·부위 보존, 답변의 문헌 일치를 별도로 확인해야 한다. `READY`는 기존 형식 검증 통과를 뜻하며 농업 전문가 검증을 뜻하지 않는다.

## 왜 이 순서로 확인하는가

저장값이 바뀌었는데 모델만 조정하면 잘못된 입력을 그럴듯하게 설명할 수 있다. 먼저 입력→DB→조회→문맥의 값을 대조한다. 다음으로 올바른 조건의 문서가 검색됐는지 확인한다. 마지막으로 모델이 그 문서가 실제로 말하는 범위 안에서 답했는지 확인한다.

이 세 단계를 구분해야 ‘단위가 사라진 문제’, ‘문서가 없는 문제’, ‘관련 문서는 왔지만 모델이 과장한 문제’를 각각 설명할 수 있다. 실패를 모델 크기 하나로 설명하거나 문서 수/유사도만으로 정확도를 주장하지 않는 이유다.
