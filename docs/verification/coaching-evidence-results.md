# 기록 코칭 근거의 적용 조건 점검 결과

2026-11-23. **문서의 적용 조건 정리와 통제 후보 선별 실험을 구현했다. 실제 코칭 답변이 더 정확해졌다는 결과는 아직 없다.** 제품 코드·DB·벡터·모델·기존 프롬프트는 변경하지 않았다. Docker/API/모델을 시작하지 않았다.

## 1. 무엇을 확인했는가

기존에는 작물명과 기술문서 여부를 필터링했지만, 같은 작물 안의 품종·수확 부위·재배 방식이 다른 문단도 답변 근거가 될 수 있었다. 이번에는 문단의 조건을 원문과 대조하고, 입력 조건과 충돌하거나 확인이 필요한 부분을 별도로 표시하는 실험 도구를 만들었다.

`APPLICABLE`은 **주석한 제한 조건에 충돌·미확인이 없는 문단**이다. 그 문단이 사용자의 질문 전체에 충분한 답을 제공하거나, 모든 문장이 모든 재배 조건에 유효하다는 뜻은 아니다. `CONDITIONAL`은 조건 미확인/범위 혼합/주석 미확보이며 `EXCLUDED`는 명시적 조건 충돌이다.

## 2. 자료와 조사 범위

| 항목 | 범위 |
|---|---|
| 기존 자료 | 원문 9개, 선택 문단 26개. 원문·선택 본문 해시 18개 전부 일치 |
| 추가 조사·선택 | 공개 공식 HTML 2개에서 짧은 발췌 4개 |
| 실험 자료 합계 | 원문 11개, 문단 30개. 기존 DB의 문서 수를 늘린 것이 아님 |
| 대상 | 천궁·참당귀·구기자나무와 8개 작업 |
| 입력 사실 | 실제 구조화 문맥 + 합성 메모의 수동 사실 주석. 자동 자연어 추출은 미실행 |
| 모델/검색 호출 | 0회. 임베딩·pgvector·API·답변 생성 미실행 |

출처·원문/선택 해시·선정/제외 이유는 [출처 목록](coaching-evidence-sources.json), 문단 30개의 조건과 사유는 [문단 감사표](coaching-evidence-audit.csv)에 있다. 기존 선택 본문을 덮어쓰지 않았다. 참당귀 매뉴얼의 저장 이미지 `page27`/`page32`는 인쇄 쪽수 28/33으로 구분하여 대조했다.

추가한 자료는 [충청북도농업기술원 구기자 재배기술](https://ares.chungbuk.go.kr/home/sub.php?menukey=1151)과 [농촌진흥청 약용작물 천궁 재배기술](https://www.rda.go.kr/middlePopOpenPopNongsaroDBView.do?no=1388)이다. 각각 부위 구분·피복의 잡초 억제, 가뭄 관리·병해 관찰 관계만 발췌했다. 발행일은 원문에서 확인하지 못해 미표시로 남겼다.

**기관이 공식적이어도 문장 전체를 현재 권장으로 채택하지 않았다.** 구기자 페이지의 제초제 일괄 금지 문장과 과거 약제·정량 권장은 현행 등록 조건을 대조하지 못해 제외했다. 의약 효능·복용·민간요법도 재배 코칭에 사용하지 않았다. 실제 제품의 작물·대상·용량·횟수 등록 적합성은 검증하지 않았다.

조건 주석은 에이전트가 원문을 대조한 예비 해석이다. `NOT_STATED`는 해당 제한을 명시하지 않았다는 뜻이며, 모든 조건에 적용됨을 증명하지 않는다. 품종별/생육기별 안내가 섞인 기존 12개 문단은 분리 전 `unresolvedScope`로 보류한다. 특히 특정 품종 전용 수치와 일반 안내를 통째로 보류하면 유용한 부분까지 줄어들 수 있어 후속 문단 분할이 필요하다.

## 3. 어떤 실험과 비교인가

- 개발 24개: 이전 실험의 실제 저장 문맥/후보 문단을 재생했다. 예전 48개 평가도 이미 알려진 개발 자료이며 새 독립 평가로 세지 않는다.
- 새 48개: 3작물×8작업×2상황의 합성 입력. 후보 문단과 기대 분류는 선택기 결과를 보기 전에 수동 작성했다.
- 새 사례의 후보는 사람이 구성한 **통제 후보**다. 기존 제품의 실제 검색 결과와 비교한 실험이 아니다. 다른 작물 문서가 의도적으로 포함돼 있는데, 현재 제품은 이미 다른 작물을 필터링하므로 그 제외를 제품의 새 개선 성과로 주장하지 않는다.
- 기대 판정·필요 근거 ID·판정 이유는 선택기 입력에 전달하지 않는다. 평가기에만 제공한다. 기대값을 바꿔도 선택 결과가 변하지 않는 회귀 검사로 확인했다.
- 사실 주석은 메모의 정확한 위치/문자열/값을 확인한다. 이것만으로 부정·추측·질문을 해석할 수는 없다. 사용자가 실제로 확정한 사실인지 수동 검토가 필요하다.
- 전체 후보를 그대로 유지하는 가상 기준도 집계했지만, 이를 기존 제품의 검색/답변 성능으로 부르지 않는다.

`evidence-v1` 입력 사례 SHA-256은 `e1f936327c741bae995f4ce29efdccab4ef1de4cf2c7c4cce556cff93b9994fa`다. 원시 실행과 최종 읽기 확인을 위한 실행은 보존하고, 같은 48개를 재실행한 횟수를 독립 사례 수에 더하지 않는다.

각 칸은 합성 2상황에 제공한 후보의 **적용/조건부/제외 건수**다. 실제 지원률이 아니다.

## 5. 대표 사례와 남은 문제

| 사례 | 확인한 동작 | 남은 한계 |
|---|---|---|
| 참당귀 실제 잎 수확 | 작물 기본 부위가 뿌리여도 실제 `LEAF`를 사용. 뿌리용 문단 제외 | 잎 전용 재배 조건은 별도로 필요 |
| 구기자 호광 품종 | 청감 전용 수형 수치의 적용 조건 충돌 표시 | 호광용 근거가 생기는 것은 아님 |
| 구기자 품종 미상 제초 | 품종을 모른다는 이유만으로 일반 피복 설명을 버리지 않음 | 실제 제초제 적합성은 판단하지 않음 |
| 구기자 뿌리껍질 수확 | 열매 숙도 문단을 제외하고 부위 구분 자료를 유지 | 부위 명칭 설명만으로 수확 시기·방법을 안내할 수 없음 |
| 천궁 가지 정리 | 다른 작물의 정리 문단을 제외 | 천궁에 해당 작업이 적절한지의 근거 미확보 |
| 가격/의약 복용 요청 | 작물/작업 조건만 맞으면 일반 문단이 남을 수 있음 | 질문 의도와 근거의 충분성을 별도로 판정해야 함 |
| 구기자 관수의 삽식 조건 | 관수 상세에 없는 번식 방식은 추측하지 않고 보류 | 메모에서 확인한 번식 사실을 안전하게 전달할 방식이 필요 |

자체 점검에서 수확 부위 `UNKNOWN`을 특정 부위와의 충돌로 처리하는 실험 코드 오류를 재현했다. 구조화 값 `UNKNOWN`은 확인 필요로 처리하도록 최소 수정하고 회귀 검사를 추가했다. 제품 코드는 수정하지 않았다.

## 6. 실행·검사·보존

정확한 명령과 파일 위치는 [사용 설명](coaching-evidence-lab.md)에 있다. 출처 검사, Python 검사, 선택기/평가기 Java 검사와 루트 전체 검사를 수행했다. 최종 숫자·리뷰 조치는 아래 최종 확인 기록에 기재한다.

원문·선택 본문·문단 사본·실행 JSON/CSV는 `.local/rag-api/evidence-selection/`에 보존했다. 원문은 Git에서 제외한다. 기존 `.local/rag-api/corpus/`, DB, Docker 볼륨, 모델은 변경하지 않았다. 로컬 포트 읽기 확인 당시 API18080·PG15433·Redis16379·Docker Ollama11436·네이티브 Ollama11437은 모두 응답하지 않았다. DB 내용을 새로 조회한 것은 아니다.

원격 Git 쓰기·설치·모델 다운로드·유료 호출·배포·앱 종료는 모두 수행하지 않았다. 공식 원문 확보에만 외부 통신을 사용했으며 사용자 기록·비밀값을 전송하지 않았다.

## 7. 다음 작업의 우선순위

1. 혼합 문단을 품종·부위·생육기별로 분리하고 각 문단의 조건을 재검토한다. 일반 안내를 살리면서 전용 수치의 잘못된 적용을 막는 것이 우선이다.
2. 필요한 자료를 확보한 범위에서 실제 pgvector 검색을 비교한다. 별도 환경 재개 승인 후 기존 벡터를 보존한 평가용 버전에만 적재한다.
3. 질문 의도와 근거 충분성을 확인하고, 확실한 안내와 필요한 확인을 함께 제공하도록 같은 모델로 비교한다. 프롬프트만 엄격하게 해서 보류를 늘린 이전 방식의 실패를 반복하지 않는다.
4. 새로운 평가 자료에서 실제 API 전체를 검증한다. 이번 통제 후보 실험을 새 독립 답변 품질 평가로 재사용하지 않는다.

현재 채택 판단: 실험 도구와 조건 목록은 보존한다. 제품 적용과 정확도 개선 완료 판단은 보류한다.
