# 기록 코칭 실제 검색 확대 설계

상태: 2026-11-25 사용자 승인. 커밋·개인 origin Draft PR은 검증과 내부 품질이 충분할 때만 수행한다. 병합·배포는 하지 않는다.

## 목적과 선택

기존 기록 코칭의 근거 선택을 개선한다. 챗봇·요청마다 웹 조사·모델 학습을 추가하지 않는다. 기존 천궁·참당귀·구기자나무에서 혼합 문단을 분리하고 도라지·고추·상추의 공식 자료를 조사한다. 약용 뿌리·열매채소·잎채소의 차이를 확인하며 전체 농업을 대표한다고 주장하지 않는다.

모델 교체·프롬프트 강화보다 자료와 적용 조건의 문제를 먼저 분리한다. 기존 엄격한 생성 정책은 유용성 감소로 미채택됐고 이번에도 생성 정책을 바꾸지 않는다.

## 자료와 비교

- 기존 원문·선택 본문·26벡터·모든 결과를 보존한다. 기존11원문/30문단의 해시를 검증하고 혼합12문단을 원문 연속 범위로 나눈다. 부모→자식 ID와 범위·조건·보류 이유를 남긴다.
- 농촌진흥청·농사로·기술원 등 공식 공개 자료를 추가 조사한다. 작물 정체성·발행/확인 시점·재배 조건을 대조한다. 의약 효능·과거 약제 처방·확인되지 않은 정량 권장은 제외한다. 자료 부족은 표시한다.
- 원문은 Git 제외 `.local/rag-api/retrieval-expansion/sources/`에 보존하고 메타데이터·해시·발췌 위치만 추적한다. 기존 파일을 수정하지 않는다.
- 비교 A/B: 기존26문단과 같은 자료의 분할본을 기존3작물의 동일 질의/설정에서 비교한다. 비교 C/D: 추가 자료를 포함한 같은6작물 corpus/후보를 조건 선별 전후 비교한다. 문단 추가 효과와 선별 효과를 혼동하지 않는다.
- 현재 제품 QueryPlanner, bge-m3, Spring AI PgVectorStore의1024차원/코사인/HNSW, topK6/threshold0.5를 기본 고정한다. 자동 임계값 튜닝·새 랭커는 이번에 추가하지 않는다.
- 기존 사례는 개발용이다. 새 평가 최대96개(6작물×8작업×2)는 검색 전 기대 근거/금지 조건/미확보를 고정한다. 부적합 조합을 정상으로 만들지 않는다. 평가를 보고 조정하면 개발용 전환한다.
- 사실 주석은 수동이며 자동 메모 해석 성능이 아니다. 문헌/조건 주석과 의미 판정의 작성자 편향·전문가 부재를 명시한다.

## 환경과 인터페이스

별도 Compose `ccc-coaching-retrieval`의 PostgreSQL만127.0.0.1:15434에 실행한다. 기존 고정 이미지, 전용 영구 볼륨, 최초0600비밀번호/DB식별표식, DB이름·스키마 검사 후에만 초기화·적재한다. 기존 사용자 컨테이너/DB·전역Docker설정을 건드리지 않는다. 기존API/Redis/DockerOllama를 실행하지 않는다.

보존된 macOS Ollama11437과 기존bge-m3만 직렬 사용한다. 새 설치·다운로드·생성 호출은 없다. 기존 프로세스/로드 모델을 먼저 확인하고 자신이 시작한 서비스만 종료한다. 자원 부족 시 해당 경로 중단과 사유를 기록한다. DB·모델은 남긴다.

Python CLI `scripts/coaching-retrieval.py`가 `check-sources`, `prepare`, `up`, `run --run NAME`, `summary --run NAME`, `stop`을 제공한다. 삭제명령은 없다. test 전용 Java 실행기는 실제 검색 후보와 조건 선택 결과를 모두 보존한다. opt-in Gradle task를 사용하며 기본test가DB를 시작하지 않는다. 결과 폴더는 덮어쓰지 않고 입력/코드/원문 해시를 잠근다.
