# 근거 부족 코칭 정책 비교 — 승인 실행 계획

목표: 기존 제품 API/DB/프롬프트를 보존한 채, 같은 기록/문서를 사용하는 기존 정책과 칭찬 생략·확인 질문·보류 정책을 비교한다. Docker/API는 중지 유지. 기존 macOS Ollama와 보존된 공식 9원문/26문단만 사용한다.

1. 사례/판정 기준 준비: 기존 24건을 조정용, 새 합성 48건을 잠금 평가용으로 구분. 기존 오류 유형 및 원문 인용 연결. 모델에 판정 정답을 전달하지 않는다.
2. 실험 도구: 실제 제품 PromptBuilder로 입력을 내보내고, 별도 출력 정책/스키마만 변경. 모델/설정/자료/사례/실행 코드 식별값 잠금, 원본 보존, 직렬 실행, 중단 후 재개, 실패 독립 집계. Docker를 호출하지 않는 기존 native 모델 시작 경로.
3. 개발 비교 후 후보 수정 최대 두 차례. 수정이 없으면 v1을 그대로 고정. 새 48건은 결과를 보고 조정하지 않는다.
4. 자체 평가: 형식/인용 ID 검사와 문헌 의미 검토 분리. 창작/조건/제품/단위 혼동, 적절한 보류, 불필요한 보류, 생성 실패, 지연을 각각 보고. 자동 채점으로 의미 성공 처리하지 않는다.
5. 관련 Python/Java 검사, ./gradlew test, 별도 최종 코드 리뷰, 로컬 역할별 커밋. push/PR/병합/배포 없음.

실험 형식만 decision(ANSWER/CLARIFY/ABSTAIN), nullable goodPoint, nextActions 0~3, questions와 missingInformation을 허용한다. 기존 형식은 goodPoint 1, nextActions 2~3을 유지한다. 모르는 농약 적합성은 판단하지 않는다. 정책/스키마 묶음 비교이며 단일 문구 효과로 주장하지 않는다.

완료: 실행/실패/제외 분모 공개, 모든 판정의 근거 보존, 재실행 명령/한계/다음 검색 개선 계획 기록. 같은 AI의 자체 검토이며 전문가·현장 효과·전체 API·실제 검색 성능 평가가 아니다. 기존 DB/모델 삭제 없음.
