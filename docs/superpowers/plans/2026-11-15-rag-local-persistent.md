# 보존형 로컬 RAG 실습 구현 계획

목표: 승인된 Docker Compose 환경에서 공식 문서·벡터 DB·기존 임베딩 모델을 보존하고 사용자가 직접 검색한다.

구조: 전용 PostgreSQL 볼륨 + 기존 외부 Ollama 캐시 볼륨. Python 명령이 수명 주기를 관리하고 명시적 실행 Java 통합 검사가 실제 Spring AI 적재·검색을 담당한다. 전체 API 앱과 답변 모델은 실행하지 않는다.

## 제약

- Java 21, Spring AI 1.1.8, PostgreSQL 16 + pgvector 0.8.5, 기존 bge-m3 digest 유지.
- 기본 loopback 포트 15432/11435. 충돌 시 기존 프로세스를 종료하지 않고 실패.
- 기존 사용자 컨테이너·볼륨·제품 코드·프롬프트 불변. 새 이미지·모델 다운로드와 외부 AI 호출 금지.
- 최신 origin/dev 기반 새 브랜치에 앞선 검증 커밋을 보존. 로컬 커밋만, 원격 쓰기 없음.
- 자료·비밀값·검색 결과·백업은 `.local/rag/`에 보존하고 Git 제외. 종료 시 볼륨 삭제 없음.

## 단계

- [x] 실행 도구: 초기 자료 검증/보존, 자격 증명 보존, 포트 충돌 거부 테스트의 실패 확인 후 구현.
- [x] 전용 Compose와 DB 식별 guard. 알 수 없는 테이블/스키마는 거부.
- [x] 명시적 Java 통합 검사: 실제 PgVectorStore 적재/검색, 본문·출처·벡터 비교, 재적재 중복 방지.
- [x] 실 DB에서 적재, 검색, 재시작, 컨테이너 재생성, 별도 임시 DB 백업 복구 확인.
- [x] 독립 리뷰 1회, 관련 검사와 루트 `./gradlew test`, 문서·결과 작성. 역할별 로컬 커밋으로 보존.

## 검토할 실패 조건

- 저장된 비밀번호 재생성으로 기존 DB 접속이 끊기지 않아야 한다.
- 모델 캐시를 다른 컨테이너가 쓰고 있거나 포트가 점유됐으면 중단한다.
- 문서·조각·metadata 변조를 적재 전에 거부한다.
- 데이터가 있는 DB의 구조를 자동 수정하지 않는다.
- 타임아웃/실패 시 DB·캐시를 정리하지 않으며 오래된 결과를 새 성공으로 표시하지 않는다.

## 결과와 다음 단계

재실행 가이드와 보존/복구 증거를 남긴다. 이 단계는 문서 2개의 실제 검색 실습이며 전체 코칭 정확도 평가가 아니다. 답변 모델과 실제 API 연결, 자료 확대/독립 평가, 성능 조정은 각각 후속 계획으로 제안한다.
